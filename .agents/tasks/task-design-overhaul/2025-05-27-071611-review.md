# Glassmorphism design overhaul (v2)

The four critical and confirmed issues from the v1 review have been addressed. `darkMode: "class"` is restored, duplicate keyframes are consolidated to the tailwind config, dead CSS variables are removed, and a `@supports` fallback exists for `backdrop-filter`. The build passes cleanly.

**Watch for:** The `@keyframes float` won't be emitted by Tailwind JIT because no component uses the `animate-float` utility class, breaking the Hero's floating pill animations that reference it via inline `style` (confirmed). The `@supports` fallback targets the `.glass` CSS class, which no component actually uses — all glass surfaces use inline Tailwind utilities instead (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

The keyframe consolidation introduced a subtle breakage. Removing the raw `@keyframes float` from `globals.css` means that animation only exists when Tailwind generates it. Tailwind JIT only emits keyframes when the corresponding `animate-*` utility is referenced in a class attribute. `animate-blob` is used in auth layout and onboarding, so `@keyframes blob` is present. `animate-float` is used nowhere — the Hero pills reference `float` only via inline `style={{ animation: "float 6s ease-in-out infinite" }}`, which doesn't trigger Tailwind's JIT scanner. Those pills will be static.

The `@supports` fallback targets `.glass`, but no component renders with that class. Every glass surface is built from Tailwind utilities (`bg-white/5 backdrop-blur-xl border border-white/10`) applied directly in JSX. The fallback is dead code in its current form.

## Broken float animation on Hero pills

The Hero component renders three floating regulation badges (GDPR, SOC2, HIPAA) with `style={{ animation: "float 6s ease-in-out infinite" }}`. After the v1 fix removed the duplicate `@keyframes` from `globals.css`, the only definition lives in `tailwind.config.ts` under `theme.extend.keyframes.float`. Tailwind's JIT compiler emits keyframe definitions only when the corresponding utility class appears in scanned content — in this case, `animate-float`.

`animate-blob` is used in three places (auth layout and onboarding), so its keyframes are emitted. `animate-float` is used nowhere. The consequence: `@keyframes float` never appears in the generated stylesheet, and the pills sit motionless.

The cleanest fix is to switch the Hero pills from inline `style` to Tailwind classes:

```tsx
<div className="absolute top-32 left-10 hidden lg:block animate-float">
```

For animation delays, use Tailwind's arbitrary property syntax already demonstrated in the auth layout: `[animation-delay:1s]`, `[animation-delay:2s]`.

## @supports fallback coverage gap

The fallback rule:

```css
@supports not (backdrop-filter: blur(1px)) {
  .glass {
    background: rgba(15, 23, 42, 0.8);
  }
}
```

No component renders with `class="glass"`. The `.glass` utility defined in `@layer utilities` is never consumed. Card, Navbar, Footer, ComplianceStats, RegulationCard, FilterBar, Features, Pricing, Testimonials, and Hero all construct their glass surfaces from Tailwind utilities directly.

The practical fix: make Card.tsx and other glass surfaces use the `.glass` class (consolidating the repeated `bg-white/5 backdrop-blur-xl border border-white/10` pattern into the utility that already exists and already has the fallback).
